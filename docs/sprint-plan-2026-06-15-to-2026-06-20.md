# TJC Stock Media Codex Autonomous Run Plan: 2026-06-15 to 2026-06-20

## Run Goal

Prove whether TJC Stock Media can safely support a real internal teammate beta using protected access, real connected data, durable state, and honest blocker reporting.

## Run Summary

- Duration: 2026-06-15 through 2026-06-20
- Total capacity: 40 hours
- Committed work: 34 hours
- Blocker buffer: 6 hours
- Primary operator: Codex autonomous agent
- Human operator: Hali for external-account access, credentials, paid services, production env changes, and go/no-go decisions
- Planning posture: proof and blocker burn-down, not new UI or broad feature expansion
- End-of-week decision: invite a small named internal beta group, or keep beta blocked with a precise remediation list

## Autonomous Run Rules

Codex should proceed without asking for routine read/search/test/doc work:
- Read repo docs, code, runbooks, and prior QA evidence.
- Run local typecheck, tests, builds, guards, smokes, and browser QA.
- Create or update project-local proof docs, run ledgers, readiness reports, and beta packets.
- Make narrow code or test fixes when a P0 proof blocker is local and reversible.
- Capture screenshots, command output summaries, and evidence paths.

Codex must stop and ask Hali before:
- Entering, revealing, rotating, or changing credentials.
- Creating paid resources or changing billing.
- Mutating Vercel production env, ResourceSpace production data, Google Drive source media, DNS, Cloudflare, or public publishing.
- Running hosted mutating smokes.
- Enabling live ResourceSpace writeback.
- Deleting, moving, renaming, or modifying source media.
- Inviting testers or declaring go for beta.

## Agent Operating Loop

For each story:
1. Inspect current state and relevant docs.
2. Write or update a run note before risky work.
3. Execute local proof first.
4. Use hosted read-only proof only when access is available and safe.
5. Fix narrow local blockers.
6. Re-run affected checks.
7. Record evidence, blockers, and next action.

Daily checkpoint format:
- Work completed.
- Evidence captured.
- Checks run.
- Blockers.
- Decisions needed from Hali.
- Next autonomous action.

## Definition Of Done

- Hosted beta access path is verified or explicitly blocked.
- ResourceSpace read path is proven with real data, or fallback/demo risk is clearly documented and blocked.
- Google Shared Drive custody model is documented with sanitized proof.
- Durable state is proven for beta-critical workflows, or missing durability fails closed and is shown honestly.
- Teammate beta packet is ready with named roles, safe test tasks, and feedback process.
- Final QA evidence passes locally and any hosted proof is read-only unless separately approved.
- Friday readiness report states: go, no-go, or conditional-go with named blockers.

## Story Details

### 1. Vercel And Protected Beta Access Proof

Objective: Prove the hosted beta is protected and role access works.

Tasks:
- Confirm canonical repo and deployment target.
- Confirm Vercel project protection is enabled.
- Verify beta login route and protected app behavior.
- Confirm env vars exist for beta auth, role passwords, writeback mode, and download-gate posture.
- Run hosted read-only smoke.
- Record screenshots or command output evidence.

Codex autonomy:
- Inspect Vercel docs, repo config, and local env expectations autonomously.
- Ask Hali only for Vercel access, env confirmation, or hosted smoke approval if missing.
- Do not set or change production env vars without explicit Hali approval.

Acceptance criteria:
- Anonymous user cannot use the beta app.
- Viewer, Contributor, Reviewer, and DAM Admin roles can log in.
- Query/localStorage role spoofing does not override server beta session.
- Writeback remains disabled or queued.
- No secrets are written into repo, docs, screenshots, or chat.

### 2. Real ResourceSpace Read Connection Proof

Objective: Prove the portal can read real DAM metadata without pretending fallback data is real.

Tasks:
- Confirm ResourceSpace host and read-only API user.
- Run ResourceSpace read smoke from local and hosted context if approved.
- Verify search, asset detail, metadata, preview, and review fields.
- Confirm demo fallback is hidden from normal teammate beta mode.
- Document fields missing from ResourceSpace or requiring mapping.

Codex autonomy:
- Inspect existing adapters, field maps, fixtures, export snapshots, and smoke scripts.
- Add narrow proof docs or smoke assertions if needed.
- Ask Hali only for real ResourceSpace endpoint/API access or approval to run hosted read proof.

Acceptance criteria:
- Real ResourceSpace record appears in Library/search.
- Asset detail shows clearance, blocker, and metadata truth from ResourceSpace/export path.
- Viewer/Contributor payloads hide source/original/private/admin fields.
- No live ResourceSpace writeback is enabled.
- If connection fails, app fails honestly instead of showing fake success.

### 3. Google Shared Drive Custody Proof

Objective: Prove Google Shared Drive remains master-original custody and portal does not mutate source media.

Tasks:
- Create sanitized custody manifest format.
- Confirm source/original ownership and folder boundary.
- Verify portal only references governed metadata/previews/approved derivatives.
- Check UI/API for normal-role source path leakage.
- Update runbook with custody proof process.

Codex autonomy:
- Create manifest template and proof checklist.
- Inspect code and API payloads for source/original leaks.
- Do not access, mutate, move, rename, delete, or commit church media files.

Acceptance criteria:
- Sanitized manifest exists without private media files or sensitive paths.
- Source/original files are not committed, moved, renamed, deleted, or uploaded through portal.
- Normal roles cannot see source paths, checksums, original URLs, or admin custody details.
- Admin documentation states Shared Drive is master copy.

### 4. Durable Beta State Proof

Objective: Prove beta-critical state is durable or unavailable by design.

Workflows:
- Feedback
- Audit log
- Download tickets
- Saved searches
- Package drafts
- Pending review/write queue

Tasks:
- Decide required store per workflow for beta.
- Configure/prove durable store where available.
- Ensure hosted runtime fails closed when durability is missing.
- Document local-only workflows as not beta-ready.
- Run storage honesty guard and relevant smokes.

Codex autonomy:
- Inspect existing storage code and guards.
- Implement narrow fail-closed fixes if local code silently claims durability.
- Ask Hali before provisioning external stores, changing hosted env, or enabling paid services.

Acceptance criteria:
- Feedback either persists durably or is disabled/fails closed.
- Audit/download ticket writes cannot silently disappear in hosted beta.
- Saved searches and package drafts are not represented as durable unless proven.
- Admin readiness surfaces show unavailable/degraded states honestly.

### 5. Teammate Beta Packet

Objective: Prepare a small, safe internal beta run.

Tasks:
- Select named testers and assign roles.
- Write role-specific tasks for Viewer, Contributor, Reviewer, and DAM Admin.
- Prepare invite copy and "do not upload sensitive media" rules.
- Define feedback collection process and triage labels.
- Define stop conditions for beta.

Codex autonomy:
- Draft packet, tester matrix, tasks, invite copy, and stop conditions.
- Use placeholder tester names until Hali supplies real names.
- Do not send invites or contact testers.

Acceptance criteria:
- Packet says ResourceSpace is private admin software, not normal teammate portal.
- Packet says Google Shared Drive keeps originals.
- Packet says packages, tags, collections, AI suggestions, and approved folders do not grant permission.
- Testers know blocked downloads are expected when rights are unclear.
- Sensitive uploads are prohibited during beta.

### 6. Final QA And Readiness Report

Objective: Produce the Friday go/no-go decision.

Tasks:
- Run local checks: typecheck, tests, build, guards, launch readiness.
- Run local smokes: API, download ticket, feedback, package, browser QA.
- Run hosted read-only smoke if access is approved and configured.
- Review screenshots at desktop/tablet/mobile widths.
- Write final readiness report.

Codex autonomy:
- Run all local checks.
- Fix narrow local regressions caused by this run.
- Present Friday decision evidence; Hali makes final invite/go decision.

Acceptance criteria:
- QA results are recorded with command names and pass/fail status.
- Known failures are classified as blocker, acceptable beta limitation, or follow-up.
- Report includes decision, evidence, blockers, owners, and next week recommendation.

## Test Scenarios

### Scenario 1: Protected Beta Login

Objective: Verify only authorized beta personas can access the portal.

Starting conditions:
- Hosted beta URL is deployed.
- Beta auth env vars are configured.
- Vercel protection is enabled.

Roles:
- Viewer
- Contributor
- Reviewer
- DAM Admin

Steps:
1. Open hosted beta URL as anonymous user. Expected: access is blocked or redirected.
2. Log in as Viewer. Expected: Library/search/detail access only.
3. Attempt query/localStorage role override. Expected: server role remains Viewer.
4. Repeat login for Contributor, Reviewer, and DAM Admin. Expected: each sees role-appropriate navigation.

### Scenario 2: Real ResourceSpace Read

Objective: Verify real DAM records can be searched and inspected.

Starting conditions:
- ResourceSpace read endpoint is configured.
- Demo fallback is disabled for teammate beta proof.

Steps:
1. Search known real record. Expected: real metadata appears.
2. Open asset detail. Expected: clearance, blockers, and metadata are visible.
3. Inspect normal-role API payload. Expected: no source/original/private/admin fields.
4. Disable ResourceSpace connection. Expected: app reports unavailable state, not fake success.

### Scenario 3: Blocked Download Safety

Objective: Verify unclear media cannot be downloaded.

Starting conditions:
- At least one asset has incomplete rights or missing derivative.

Steps:
1. Open blocked asset as Viewer. Expected: download is unavailable.
2. Request review if allowed. Expected: review/request path is shown.
3. Inspect response payload. Expected: no source path, original URL, checksum, or private admin data.

### Scenario 4: Contributor Intake Safety

Objective: Verify upload/intake does not publish or approve media.

Starting conditions:
- Contributor role is available.

Steps:
1. Open Send media/upload flow.
2. Submit harmless test metadata only.
3. Confirm receipt. Expected: status is Needs Review / Do Not Publish.
4. Search as Viewer. Expected: submitted item is not self-serve reusable.

### Scenario 5: Durable Feedback And Audit

Objective: Verify hosted state is durable or fails closed.

Starting conditions:
- Hosted runtime is configured.
- Durable store is either present or intentionally absent.

Steps:
1. Submit feedback. Expected: durable success or explicit unavailable state.
2. Trigger download-ticket or audit-writing workflow. Expected: write persists or fails closed.
3. Restart/redeploy if safe. Expected: durable state remains if claimed durable.

## Risks And Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Vercel/env access unavailable | Cannot prove hosted beta | Use buffer, document exact missing access, keep no-go decision honest. |
| ResourceSpace API not ready | Cannot claim real connected DAM | Prove local/export path only and block teammate beta as real DAM. |
| Durable store not configured | Feedback/audit/tickets unsafe | Disable or fail closed; do not invite testers for workflows needing durability. |
| Real media rights unclear | Accidental misuse risk | Use safe sample tasks and blocked-download checks only. |
| Demo/fallback data leaks into beta | Stakeholders overtrust system | Add visible unavailable states and fail beta proof until fixed. |
| Scope creep into UI polish | Proof work slips | Only fix P0 blocker bugs; defer cosmetic changes. |

## Out Of Scope

- Public launch.
- Broad teammate rollout.
- Paid infrastructure changes without approval.
- Live ResourceSpace writeback.
- Public sharing, CDN, embeds, or original/source delivery.
- AI approval of rights.
- Full archive import.
- Moving, renaming, deleting, or mutating source media.

## Friday Decision Rubric

Go for tiny internal beta only if:
- Hosted access is protected.
- Real ResourceSpace read proof works or beta is explicitly scoped to non-real rehearsal.
- Source/original custody is safe.
- Critical state is durable or unavailable by design.
- Viewer/Contributor redaction passes.
- Test packet is ready.

No-go if:
- Demo/fallback data can look real.
- Normal roles can see source/original/private/admin details.
- Blocked media can download.
- Hosted state silently disappears while reporting success.
- Vercel/ResourceSpace/Drive proof cannot be captured.

Conditional-go if:
- Access and safety pass, but one non-critical workflow is disabled and clearly communicated.
